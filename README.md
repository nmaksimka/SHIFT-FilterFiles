# FilterFiles

Тестовое задание ШИФТ: консольная утилита, которая читает текстовые файлы и раскладывает строки по типам: целые числа, вещественные числа и строки. Каждый тип пишется в свой файл, по желанию выводится статистика.

## Требования

- Java 21 или новее (проверено на 21 и 25).
- Maven ставить не нужно, в проекте есть Maven Wrapper (`mvnw`). Сборка использует Maven 3.9.16.
- Зависимостей в рабочем коде нет. Для тестов подключены JUnit 5.14 и AssertJ 3.27.

## Сборка и запуск

```powershell
.\mvnw.cmd package
java -jar target/filterfiles.jar -s -a -p sample- examples/in1.txt examples/in2.txt
```

На Linux и macOS используйте `./mvnw`. Команда `package` сначала прогоняет тесты.

## Опции

| Опция | Что делает |
|---|---|
| `-o <путь>` | папка для результатов, по умолчанию текущая; создаётся, если её нет |
| `-p <префикс>` | префикс имён: `-p sample-` даст `sample-integers.txt` |
| `-a` | дописывать в существующие файлы, по умолчанию файлы перезаписываются |
| `-s` | краткая статистика: сколько элементов каждого типа |
| `-f` | полная статистика: для чисел минимум, максимум, сумма и среднее, для строк длина самой короткой и самой длинной |
| `-h`, `--help` | справка |
| `--` | всё после этого считать именами файлов |

Опции можно писать в любом порядке, в том числе после файлов. Если указать и `-s`, и `-f`, выводится полная статистика. Без `-s` и `-f` статистика не печатается.

## Пример

`examples/in1.txt` и `examples/in2.txt` из условия задачи:

```powershell
java -jar target/filterfiles.jar -f -p sample- examples/in1.txt examples/in2.txt
```

```
Целые числа: 3
  минимум: 45
  максимум: 1234567890123456789
  сумма: 1234567890123557334
  среднее: 411522630041185778
Вещественные числа: 3
  минимум: -0.001
  максимум: 3.1415
  сумма: 3.1405000000000000000000001528535047
  среднее: 1.046833333333333333333333384284502
Строки: 6
  самая короткая: 4
  самая длинная: 42
```

Появятся три файла:

- `sample-integers.txt`: `45`, `100500`, `1234567890123456789`;
- `sample-floats.txt`: `3.1415`, `-0.001`, `1.528535047E-25`;
- `sample-strings.txt`: шесть строк текста.

## Правила классификации

- **Целое**: необязательный знак и цифры: `45`, `-0`, `+5`. Длина не ограничена: `99999999999999999999` тоже целое.
- **Вещественное**: десятичная точка или экспонента: `3.1415`, `.5`, `1.`, `1e10`, `1.528535047E-25`.
- **Строка**: всё остальное, в том числе `1,5`, `0x10`, `NaN`, `1 000`.
- Пустые строки и строки из одних пробелов пропускаются.
- Пробелы по краям не мешают распознать число. Числа записываются без них, а строки сохраняются как есть.
- BOM в начале файла (его ставит Блокнот) убирается.

## Поведение при ошибках

- **Нет файла или он не в UTF-8.** Утилита сообщает об этом в stderr и продолжает с остальными файлами. Строки, прочитанные до ошибки, сохраняются.
- **Ошибка записи одного выходного файла** не мешает записать остальные.
- **Файлы результатов** создаются только тогда, когда для них есть данные.
- **В режиме `-a`** новая строка не склеится с последней, даже если в существующем файле нет перевода строки в конце.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | всё обработано |
| `1` | часть файлов не прочитана или не записана |
| `2` | неверные аргументы |

## Как устроено

```
Main                 точка входа, только вызывает FilterFiles и возвращает код выхода
FilterFiles          читает файлы по очереди, построчно, без загрузки целиком в память
cli/ArgumentParser   разбор аргументов в неизменяемый Options
core/LineClassifier  определение типа строки регулярными выражениями
stats/*              статистика на BigDecimal: без переполнения и потери точности
files/ResultWriter   ленивое открытие выходных файлов и потоковая запись
```

- **Нет переполнения.** Числа считаются в `BigDecimal`, поэтому сумма больших `long` не переполняется, а `1e999` не превращается в `Infinity`.
- **Без лишней памяти.** Строки сразу пишутся в файлы и в память не копятся, поэтому большие входные файлы не приводят к `OutOfMemoryError`.
- **Вывод через параметры.** `FilterFiles` получает `PrintStream` для вывода и не вызывает `System.exit`. Поэтому всю утилиту можно проверить тестами без запуска отдельного процесса.

## Тесты

```powershell
.\mvnw.cmd test
```

66 тестов:

- **классификация:** граничные случаи из условия и больше;
- **разбор аргументов:** опции без значения, неизвестные опции, опасные префиксы;
- **статистика:** переполнение, точность, `1e999`, кириллица в длине строк;
- **сквозные сценарии на временных файлах:**
  - пример из задания;
  - режим `-a`;
  - BOM;
  - файл не в UTF-8;
  - отсутствующий файл;
  - выходная папка, которая на самом деле файл.
